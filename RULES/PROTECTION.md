# 🔒 PROTECTION — how the rules are locked, and how to carry them to a new project

## The problem this solves

Coding agents kept rewriting and deleting `CLAUDE.md` in new projects, so the standing C++ rules
were lost. An instruction ("do not edit this file") is not enough on its own — so the lock is
**enforced at four independent layers**:

| Layer | File | What it stops |
|---|---|---|
| 1. Instruction | `CLAUDE.md` | Tells the agent the rules are user-owned and why. |
| 2. Permissions | `.claude/settings.json` → `permissions.deny` | The agent's Edit/Write tool calls on locked paths are denied before execution. |
| 3. Hook | `.claude/hooks/guard_locked_rules.py` (PreToolUse) | Hard-blocks Edit/Write/MultiEdit **and** Bash workarounds — `rm`, `mv`, `cp`, `sed -i`, `patch`, `>`, `git checkout/restore/apply`, `core.hooksPath`, `git commit --no-verify`. Exit code 2 feeds the reason back to the agent. |
| 4. Git | `.githooks/pre-commit` (activated with `git config core.hooksPath .githooks`) | No commit can silently rewrite the rules; the guard itself is also guarded. |

**Locked paths:** `CLAUDE.md`, `RULES/**`, `.claude/settings.json`, `.claude/hooks/**`, `.githooks/**`.

Reading is never blocked — agents can and must read the rules. Only modification is locked.

## Escape hatch (yours, not the agent's)

- Edit a locked file normally in your own editor — the permissions and hooks only gate the
  *agent's* tools, never yours.
- Commit rule changes yourself with: `git commit --no-verify` (the pre-commit guard ignores no
  one, so this flag is the human bypass).
- Temporarily disable the agent-side hook: comment out the `"hooks"` block in
  `.claude/settings.json`.

## Install into a NEW project

1. Copy four paths from this repo into the new project root:
   - `CLAUDE.md`
   - `RULES/` (all three files)
   - `.claude/` (both `settings.json` and `hooks/guard_locked_rules.py`)
   - `.githooks/`
2. In the new project run: `git config core.hooksPath .githooks`
3. Optional but recommended — add the global memory snippet below so the rules follow you into
   *every* project, even ones that don't have the kit yet.

Requirements: Python 3 reachable from Claude Code's shell (on Windows, `python` also works —
the hook command tries `python3` then `python`). The git hook is plain POSIX `sh`.

## Global memory snippet — paste into `~/.claude/CLAUDE.md`
(Windows: `%USERPROFILE%\.claude\CLAUDE.md`)

```text
## Locked coding rules (user-owned — never modify)

- In every project, CLAUDE.md and RULES/ hold my locked rules. They override your defaults.
- NEVER edit, delete, rewrite, shorten, summarise or move CLAUDE.md, RULES/**,
  .claude/settings.json, .claude/hooks/** or .githooks/**. If a rule blocks you,
  stop and ask me.
- Before writing any C++: read CLAUDE.md, RULES/00-LOCKED-RULES.md and RULES/SKILL-Naming.md.
  C++20 always. Shared algorithms are written once as templates — no per-type copies.
  Naming per RULES/SKILL-Naming.md.
- Starting a fresh project for me: copy in the locked kit (CLAUDE.md, RULES/, .claude/,
  .githooks/) from my rules repo and run: git config core.hooksPath .githooks
```

## Changing a rule legitimately

1. You edit the file in your own editor.
2. You commit: `git commit --no-verify -m "rules-update: <what changed and why>"`.
3. The `rules-update:` prefix keeps the rule history auditable at a glance.
