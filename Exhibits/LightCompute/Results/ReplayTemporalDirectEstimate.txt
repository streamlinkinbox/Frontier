# Fresh and temporal direct-NEE comparison

## Outcome

**This validates only the NEE contribution, not total radiance.** The test-only audit shader records the selected path's direct-NEE luminance, then applies the reservoir normalization stored for the selected candidate. BSDF continuation/emitter-hit and environment contributions are excluded from the compared quantity. The production estimator and shader were not changed.

The CPU reference midpoint-integrates the overhead emitter's area with explicit visibility against the two fixture blockers. It evaluates the existing independent double-precision CPU BRDF reference for the metal receiver and applies the emitter's Rec. 709 luminance. It is independent of the GPU light sampler, RNG, ray-intersection implementation, temporal selection, and reservoir weighting; it deliberately shares the documented material model rather than claiming an independent physical BRDF.

## Fixture and validation

- SwiftShader Subzero Vulkan, Slang 2026.14.1, Release build.
- Four modes: fresh1/fresh4 reset history; temporal1/temporal4 replay a four-frame moving-receiver sequence. Suffix is the candidate count. Every mode uses the same 32 seed cohorts.
- 512 checkerboard holdout pixels per cohort and mode (16,384 samples per mode). The final holdout receiver is at x = 1.35; the emitter is a 4 × 4 overhead quad with RGB emission (10, 8, 5). The fixture has two occluders.
- Fine 2048² reference: **1.84228818752 luminance**. Coarse 1024² reference: **1.84907442424**; difference **0.00678623672**, inside the predeclared absolute convergence tolerance **0.00921144094** (0.5% of max(1, |reference|)).
- Mean gate per mode: `abs(mean - reference) <= 6 × batch_SE + reference_tolerance`. RMSE is pixel-sample RMSE against the fine reference. Gate failures are reported as failures, not suppressed.

| Mode | Mean luminance | Delta vs reference | Batch SE | RMSE | Mean gate |
|---|---:|---:|---:|---:|:---:|
| fresh1 | 1.85453688558 | +0.01224869806 (+0.665%) | 0.0299444386 | 3.76991648 | PASS |
| fresh4 | 1.83161989307 | −0.01066829445 (−0.579%) | 0.0145219505 | 1.88207686 | PASS |
| temporal1 | 1.67851367848 | −0.16377450904 (−8.890%) | 0.0170516458 | 2.24647603 | **FAIL** |
| temporal4 | 1.77531980961 | −0.06696837791 (−3.635%) | 0.0115256609 | 1.61239783 | PASS |

## Interpretation and decision

The fresh1/fresh4 controls and temporal4 pass this fixture's broad six-SE mean gate. **Temporal1 fails**, with its mean 8.89% below the reference and outside its gate. Thus the fresh and temporal estimator family is not uniformly validated; do not promote or change estimator behavior based on this comparison. The failed mode is retained visibly in the chart. The result does not establish production-scene correctness, total-radiance unbiasedness, physical-GPU/Windows behavior, or Frontier editor integration.

The previously recorded controlled-emitter visibility audit remains a separate result: its per-sample blocked/no-ray NEE guard passed on this fixture and its baseline was preserved. This estimate-only run did not rerun that 32,768-row audit. The prior audit report is `ReplayTemporalDirectVisibility.txt`.

## Motion-isolation control

A paired stationary control keeps the final receiver pose (x = 1.35), emitter, blockers, material, cohort seeds, estimator modes, and reference fixed, but holds the receiver pose constant across all four replay frames. It is run through the same SwiftShader pipelines and NEE-only extraction. Fresh controls are identical cohort-by-cohort between moving and stationary runs, as expected because both evaluate the same final scene with the same seeds.

| Mode | Moving mean | Stationary mean | Stationary − moving, paired cohort mean | Stationary gate |
|---|---:|---:|---:|:---:|
| fresh1 | 1.85453688558 | 1.85453688558 | 0 | PASS |
| fresh4 | 1.83161989307 | 1.83161989307 | 0 | PASS |
| temporal1 | 1.67851367848 | 1.85352955247 | +0.17501587399 (paired SE 0.0155352) | PASS |
| temporal4 | 1.77531980961 | 1.84548965967 | +0.07016985006 (paired SE 0.0108952) | PASS |

With the receiver stationary, **all four modes pass**; temporal1 moves from 8.89% low to 0.61% high relative to the same CPU reference. This isolates the failure to the moving-sequence condition rather than temporal resampling in this stationary fixture. The evidence does **not** identify the precise mechanism: motion reprojection/validation, motion-induced visibility changes, or their interaction remain to be separated. No estimator change is justified. The paired-control chart is `../ReplayTemporalDirectEstimateStationary.svg`; stationary runtime log is `_ClaudeScratch/provenance/direct-estimate-stationary.log` (outside Git).

## Clear-visibility moving-receiver control

The follow-up preserves the four-frame moving receiver sequence and final x = 1.35 pose, emitter, material, seed cohorts, estimator modes, and NEE-only measurement, while removing both fixture blockers. The CPU area integral uses the same BRDF/emitter reference with blocker visibility disabled. This isolates the effect of blocker visibility in this fixture; it does not change the estimator.

- 32 cohorts × 512 holdout pixels per mode (16,384 estimates per mode); SwiftShader Subzero Vulkan.
- Fine 2048² clear-scene reference: **5.37194399226 luminance**. Coarse 1024²: **5.37194528306**, difference **0.00000129080**, within the predeclared tolerance **0.02685972**.
- The same mean gate is applied: `abs(mean - reference) <= 6 × batch_SE + reference_tolerance`.

| Mode | Mean luminance | Delta vs clear reference | Batch SE | RMSE | Mean gate |
|---|---:|---:|---:|---:|:---:|
| fresh1 | 5.32533171312 | −0.04661227914 (−0.868%) | 0.0736569608 | 11.1543657 | PASS |
| fresh4 | 5.34583492098 | −0.02610907128 (−0.486%) | 0.0486561461 | 5.66561183 | PASS |
| temporal1 | 5.37206621680 | +0.00012222454 (+0.002%) | 0.0465856817 | 6.64918702 | PASS |
| temporal4 | 5.35222277530 | −0.01972121696 (−0.367%) | 0.0405961930 | 4.64711461 | PASS |

**Temporal1 passes when both blockers are absent.** In the blocked moving fixture it was 8.89% below its reference and failed; the blocked stationary control passed at 0.61% above its reference. Together, these results make blocker/visibility changes a leading suspect for the moving-only miss, rather than showing that motion alone is sufficient to cause it. This remains diagnostic, not causal proof: removing blockers changes the direct-visibility distribution, and further targeted attribution is needed before any estimator modification. The clear-scene temporal1 RMSE is still 6.649, despite its batch mean passing, so this is not a claim of per-pixel accuracy.

All four clear-scene mean gates pass; the run reports `estimator_math_changed=0`. The 10/10 CTest suite and 6/6 summary/parser tests pass. The chart is `../ReplayTemporalDirectEstimateClearMotion.svg`; full run log is `_ClaudeScratch/provenance/direct-estimate-clear-motion.log` (outside Git). Evidence remains fixture-scoped and NEE-only; it does not establish total-radiance unbiasedness, production-scene correctness, physical-GPU/Windows behavior, or editor integration.

## Single-occluder moving-receiver ablation

To distinguish whether the failure follows generic receiver motion, the original fixture blocker, or the added overhead-emitter blocker, the same four-frame moving receiver, emitter, materials, seeds, and NEE-only estimator modes were run with one blocker at a time. The `base_only` arm retains the original mixed-material fixture quad at z = 1; `added_only` retains the additional test quad at z = 1.5. Both use 32 cohorts × 512 holdout pixels per mode. Both scenarios ran in one SwiftShader process, with the same per-mode cohort seeds across scenarios.

Fine/coarse CPU references: `base_only` = **5.37194399226 / 5.37194528306** (delta **0.00000129080**); `added_only` = **1.84228818752 / 1.84907442424** (delta **0.00678623672**). Both meet the same predeclared reference convergence tolerance used by their matching visibility controls.

| Occluder | Mode | Mean | Delta vs reference | Batch SE | RMSE | Gate |

| base_only | fresh1 | 5.32533171312 | −0.04661227914 (−0.868%) | 0.0736569608 | 11.1543657 | PASS |
| base_only | fresh4 | 5.34426227384 | −0.02768171842 (−0.515%) | 0.0487278489 | 5.66120615 | PASS |
| base_only | temporal1 | 5.36925822127 | −0.00268577099 (−0.050%) | 0.0471887706 | 6.64324021 | PASS |
| base_only | temporal4 | 5.35041562154 | −0.02152837072 (−0.401%) | 0.0411527052 | 4.64107634 | PASS |
| added_only | fresh1 | 1.85453686333 | +0.01224867581 (+0.665%) | 0.0299444397 | 3.76991653 | PASS |
| added_only | fresh4 | 1.83145753051 | −0.01083065701 (−0.588%) | 0.0144230528 | 1.88661340 | PASS |

The original blocker alone behaves like the clear-visibility motion control: temporal1 passes, and its reference is numerically the same as the no-blocker scene for this final receiver pose. The added z = 1.5 blocker alone reproduces a temporal1 mean miss, while fresh1, fresh4, and temporal4 pass. Its temporal1 error is close to the two-blocker moving failure (−7.742% versus −8.890%). This narrows the fixture-level suspect to the added blocker’s visibility footprint, rather than motion alone or the original blocker alone. It does **not** yet prove which visibility transition or reservoir-history mechanism causes the miss; no estimator changes were made.
