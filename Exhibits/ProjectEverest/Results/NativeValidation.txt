- GCC 12.2.0; CMake 4.4.4; Ninja 1.13.2; C++20.

## Build and test commands

```sh
$PWD/.venv/bin/cmake -S Exhibits/ProjectEverest/Code -B Build/ProjectEverest -G Ninja
$PWD/.venv/bin/cmake --build Build/ProjectEverest --target Frontier FrontierNativeEntry NativeProjectValidation NativeUIEvidence -- -j 4
$PWD/.venv/bin/ctest --test-dir Build/ProjectEverest --output-on-failure
```

Result: all four tests passed — `NativeProjectValidation`, `FrontierProjectZeroHeadless`, `NativeProjectBrowserFlow`, and `NativeProjectEverestWorkspace`.

The compiler emitted non-fatal warnings from pinned ThorVG/STB and existing UI sources; all requested targets linked or compiled successfully. `FrontierNativeEntry` is an object-only compile of the real GLFW-backed `FrontierMain.cpp` path. `NativeUIEvidence` is a local exhibit runner, not a delivered product binary.

## Limits

No GLFW OS window was launched, and no Vulkan renderer, ReSTIR pipeline, scene, RTX hardware path, or GTX SDF/BVH fallback was run. The C++ workspace deliberately states that the scene canvas/renderer is disconnected. The work validates the native UI flow and record/Inspector lifecycle only; it does not claim native GPU rendering or hardware-path correctness.
