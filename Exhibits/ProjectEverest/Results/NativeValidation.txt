## Browser and workspace evidence

- The native chooser is the existing `.frontier` project-list flow from the SultanAladin main/UI branch. The capture calls the same `ConstructProjectBrowserInterface` used by `RunBrowserWindow`; it clicks the Project Everest row and verifies `Frontier/Projects/Project-Everest/ProjectEverest.frontier`. There is no added application-selection page and no `.projectspace` catalogue substitution.
- The workspace capture reports **all 10 custom VehicleHMI Outliner SVG symbols ready**: Environment folder, Sun, Atmosphere, Clouds, Fog, Local Cloud, Local Fog, Stars, Moon, and Lens Flare.
- Custom SVG artwork is loaded and rasterized using ThorVG into the existing ImGui dynamic-texture presentation. Approved vector variants retain source fingerprints for SVG filter primitives outside the pinned ThorVG SVG subset. Stroke icons use the pinned Lucide 1.57.0 path geometry in the native glyph renderer.
- The CPU evidence rasterizer samples `ImTextureData` so the checked-in workspace capture includes the ThorVG-generated icons.

The checked-in evidence files are:

- `Images/NativeProjectSelection.png` — 1440 × 900; existing `.frontier` project list.
- `Images/NativeWorkspace.png` — 1920 × 1080; Outliner, selected Sun Inspector, idle Viewport, and Log Stream.

The workspace harness exercises the production Control Centre, PanelDockspace, Outliner, Inspector, and Log Stream units in deterministic ImGui frames. It does not call `RunProjectWindow`; the CPU rasterizer stands in for GPU presentation.

## Limits

No GLFW OS window or Vulkan presentation was launched. No scene renderer, ReSTIR pipeline, RTX hardware path, or GTX SDF/BVH fallback was run. The native workspace explicitly leaves the scene canvas empty and reports the disconnected renderer. This validates the native UI flow, icon asset loading, and record/Inspector lifecycle only; it does not claim GPU rendering or hardware-path correctness.
