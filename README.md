# Frontier Fluid

**Real-time fluid simulation for games, in WebGPU** — a FluidNinja-style shallow-water solver for oceans, rivers, shallow water, puddles and mud, with ballistic splash particles, simulated foam, computed caustics, buoyancy and full vehicle interaction. No scrolling normal maps, no keyframed waves: the rendered water surface *is* the simulated surface.


|---|---|

Drive through the river ford and puddles and watch bow waves, wheel rooster-tails, mud churn, droplet spray that lands and foams, crates bobbing on real wave slopes.

## What's actually simulated (and what isn't)

This is a **2D shallow-water (heightfield) solver** — the same family of technique FluidNinja LIVE uses in Unreal, and the right trade-off for real-time games. It solves, per grid cell, water depth `d` and horizontal velocity `v`:

```
∂d/∂t + ∇·(d·v) = sources − sinks
∂v/∂t + (v·∇)v = −g·∇(bed + d) + viscosity + bed friction + wind + flow forcing
```

Wave speed is physically `c = √(g·d)`: waves genuinely slow down, steepen and break as water shallows; they reflect off banks, refract over the bed, pool into puddles, slosh in truck wakes and flow downhill along the river. Everything the gameplay feels — currents pushing crates, the truck slowing in deep water, surf shoving the boat — comes out of these fields.

Built on top of the solver:

| Feature | Technique |
|---|---|
| **Splash spray** | GPU ballistic droplet pool, emitted where the solver's splash-energy field is high (wheel churn, plunges, breaking crests). Droplets arc under gravity and, on landing, spawn foam **and feed a ripple back into the solver**. |
| **Foam** | Two coupled *simulated* systems, not a depth-fade shader trick: (1) an advected foam-density field generated by flow compression, crest steepness, shore wash and churn, transported by the simulated velocity; (2) foam *particles* (flecks) that live on the surface, ride the current, pile up at shorelines and pop over seconds. |
| **Caustics** | Computed every frame from the simulated surface: sun rays are refracted (Snell) through the actual wave normals, marched to the bed, and their focusing (ray-bundle Jacobian) is scattered into a caustic map the terrain shades with. Move the waves, the caustics move — same waves. |
| **Vehicles** | Wheels + hull are volume-displacing interactors: they depress the surface, drag water along, throw outwash and deposit churn energy. The solver turns that into bow waves, wakes and rooster tails. |
| **Buoyancy** | Downsampled sim readback on the CPU; rigid bodies sample surface height/velocity at probe points and get Archimedes force + torque + current drag. |
| **Rivers** | A spline bakes a carved, monotonically-descending channel + parabolic flow field into the terrain data; a source feeds the head, a sink drains the mouth. Dam it with the truck and watch it pool. |
| **Ocean** | Sponge-layer open boundary + swell injection; surf physics emerges from the equations, including breaking (steepness-driven foam/spray). |
| **Mud** | One material preset away: high viscosity (Jacobi diffusion, unconditionally stable), high density (things float higher), opaque absorption, thick slow spray. |
| **Wetness** | Terrain remembers where water has been (darkens, gets glossy, dries slowly) — shorelines and splash zones read correctly. |
| **Rain** | Adds real volume + stochastic impact rings through the solver. Puddles grow; with evaporation on, they dry out again. |

Honest limits: it is a heightfield — no overturning/curling wave lips, no underwater volume, no thin-sheet waterfalls (approximate those with sources + particles). One optional cosmetic layer exists — flow-advected micro-detail normals for sub-grid sparkle (normals only, never moves water; toggle it off for pure-sim).

## Use it in your engine

`src/fluid/` is renderer-agnostic and dependency-free. The demo engine bits live in `src/engine/` + `src/demo/` and can be ignored.

```ts
import { FluidSim, WATER_PRESET, RiverPath } from './fluid';

const sim = new FluidSim(device, { ...WATER_PRESET, resolution: 256, worldSize: 120 });

// terrain heights + river flow (res×res Float32Arrays)
const river = new RiverPath([{x:-40,z:-30,y:1.2},{x:0,z:0,y:0.2},{x:30,z:25,y:-0.8}],
                            { width: 3.4, depth: 1.1, speed: 1.7 });
river.bakeInto(heights, flowX, flowZ, channel, 256, 120, [0, 0]);
sim.setBed(heights, flowX, flowZ, channel);
sim.reset(encoder);

// every frame:
sim.step(encoder, dt,
  [ { kind: 0, position: wheelPos, velocity: wheelVel, radius: 0.48, halfHeight: 0.42, strength: 1 } ],
  [ river.getSource(), river.getSink() ],
  sunDirection);

// gameplay queries (1-frame latency readback):
const s = sim.sampleWater(x, z);   // { height, depth, velocity, normal }

// render `sim.fieldView` (depth/velocity/energy), `sim.foamView`,
// `sim.causticsView` with your own material — or use WaterRenderer /
// ParticleRenderer from this package.
```

Buoyancy for rigid bodies: `new BuoyantBody(pos, { halfExtents, mass })`, then `body.update(dt, sim)` and feed `body.toInteractor()` back into `sim.step(...)` so floating things displace water too.

Presets in `src/fluid/types.ts`: `WATER_PRESET`, `MUD_PRESET`, `OCEAN_PRESET` — every solver and material knob (viscosity, density, absorption, IOR, friction, particle budgets…) is one settings object you can blend at runtime; the demo's Water/Mud buttons swap materials live without a rebuild.

## Performance notes

- Solver cost scales with grid: 256² ≈ well under 1 ms on a discrete GPU; 512² a few ms. Substeps use a fixed-timestep accumulator (refresh-rate independent wave speed), capped per frame.
- Particles are fully GPU-resident ring buffers (zero CPU cost, zero allocation): 48k splash + 64k foam by default.
- The only readback is a 128² downsample for CPU gameplay queries, double-buffered and async (1 frame latency, never stalls).
- Caustics run at sim resolution and can be toggled off; reflections are a half-res planar pass.

Tuning & stability rules (CFL etc.) are documented in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Repository layout

```
src/fluid/          THE PACKAGE (copy this into your engine)
  FluidSim.ts       solver orchestration, passes, readback, queries
  types.ts          settings + presets (water / mud / ocean)
  RiverPath.ts      spline → carved channel + flow field + source/sink
  Buoyancy.ts       probe-based rigid-body buoyancy
  WaterRenderer.ts  surface material (displaced by the simulated field)
  ParticleRenderer.ts spray + foam particle rendering
  shaders/          WGSL: swe, foamField, particles, caustics, downsample, water…
src/engine/         minimal demo engine (renderer, camera, terrain, boxes)
src/demo/           the playable demo (scenes, truck, UI wiring)
tools/              WGSL validation script (`npm run validate-wgsl`)
docs/               architecture deep-dive
```
